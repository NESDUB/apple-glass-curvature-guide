01 / fixed-height vessel

Pills: width changes, height does not.

Change the width to see how the two measured caps stay identical. The incorrect example is intentionally generated using a different rule.

DO · class-fixed height, measured caps

DON'T ·

Magnified cap overlay

Blue: fitted geometry. Orange: selected incorrect geometry. Equal coordinate scale, not independently stretched.

DO

  • Lock the border-box height at the selected class: 36pt or 28pt.
  • Use the same class-specific end-cap extent at every width.
  • Center contents vertically; increase width for added controls.
  • Prevent cap compression with a minimum width and overflow policy.

DON'T

  • Let content, padding or zoom text dictate height.
  • Use a semicircle or generic rounded capsule as a substitute.
  • Stretch an already-drawn SVG to different aspect ratios.
  • Adjust curvature by adding shadows or outside strokes.
02 / intrinsic-size vessel

Menus: extend straight edges, not corners.

The same eight-cubic path covers compact and tall menus. Change dimensions while retaining the fitted corner extent.

DO · constant corner extent

DON'T ·

Magnified corner overlay

Compare the actual path segments at the same logical scale.

DO

  • Keep the 18.327pt transition extent fixed.
  • Reflect one symmetric double-cubic corner to all four corners.
  • Allow menu width and height to follow content independently.
  • Preserve zero-curvature joins into straight sides.

DON'T

  • Use percentage-based radii or proportional corner scaling.
  • Replace continuous corners with simple circular arcs.
  • Stretch the complete menu artwork to fit more rows.
  • Trace translucent color bleed or shadow as part of the shape.
03 / dialog vessel

Dialogs: same corner function, different extent.

The observed 260 × 172pt dialog uses the menu's normalized profile with a 39.774pt fitted extent. Both actions are 28pt high. Change the dialog dimensions independently; neither corner extent nor action height changes.

DO · dialog preset, action preset

DON'T ·

Magnified dialog corner overlay

Blue: scaled menu profile. Orange: selected incorrect geometry.

DO

  • Reuse normalized menu coefficients with the dialog extent.
  • Keep action height at 28pt and adjust width only.
  • Treat 260 × 172pt as a reference, not a universal dialog size.

DON'T

  • Apply the toolbar's 36pt height to dialog actions.
  • Use the smaller menu corner extent unchanged or double it blindly.
  • Claim a new Apple size class without measured evidence.

05 / measured evidence

What the measurements support.

Pill family: unchanged coefficients tested against two widths

Previous model: 0.0839px / 0.0846px RMS. Circular caps: 0.1765px / 0.1779px RMS.

Menu family: rasterized SVG against actual reference corners

Refined analytical fit: 0.0429px RMS. Exported SVG: 0.0739px / 0.0801px RMS.

Dialog: scale-only transfer of menu geometry

Scale-only RMS 0.0904px; independent double-cubic refit 0.0705px; circular 0.3878px. One dialog capture; the fixed extent is a local preset policy.

Action buttons: 28pt height, shared cap profile

Shared analytical cap RMS 0.1255px / 0.1393px versus circular 0.1725px / 0.1828px. Historical fit evidence, not a new raster test.

These are capture-pixel results at 2×. The models reproduce observed silhouettes, not confirmed Apple source code. Optical effects and unmeasured component classes are outside the validated scope.
